# Методика поиска лучших LLM среди доступных на router.ai
## Описание задания
Для работы OpenClaw проанализировать и предложить доступные LLM на router.ai. По критериям: стоимость (минимальная), количество токенов, ориентация на агентное использование, количество параметров.
## Ход исследования
## 1. Подготовка данных для поиска
Для начала исследования было необходимо подготовить данные для поиска моделей. Главной сложностью этого этапа было то, что на RouterAI не указывается количество параметров модели. Поэтому брались модели которые имеются и на RouterAI, и на HuggingFace, так как там есть информация о количестве параметров. В ходе этого этапа была получена общая таблица моделей с количеством параметров, входной/выходной ценой за токены, типами данных ввода/вывода(здесь представлены только те модели, которые получают на вход текстовый тип данных) и длиной контекста.
## 2. Поиск решения 
В ходе этого этапа нужно было найти пять лучших кандидатов для облачного тестирования по следующим критериям: входная цена за токены, агентная поддержка, размер контекста и количество параметров. Для понадобилось решить задачу многокритериальной оптимизации. Среди основных алгоритмов: SAW и TOPSIS. Был выбран TOPSIS по следующим причинам:

| Критерий сравнения | SAW | TOPSIS | Обоснование выбора TOPSIS |
|---|---|---|---|
| Принцип ранжирования | Рассчитывает итоговый балл как взвешенную сумму нормализованных критериев | Оценивает близость каждой LLM к идеальному и удалённость от анти-идеального решения | TOPSIS учитывает не только степень соответствия критериям, но и расстояние до худшего варианта |
| Разнонаправленные критерии | Поддерживает после предварительного преобразования cost-критериев | Непосредственно учитывает benefit- и cost-критерии при формировании идеального решения | В задаче одновременно используются критерии, которые необходимо максимизировать (`agent_score`, `context`) и минимизировать (`input_price`, `parameters`) |
| Учет качества LLM | Через вес `agent_score` | Через вес `agent_score` и расстояние до идеального решения | TOPSIS позволяет учитывать качество модели в совокупности с ресурсными характеристиками |
| Учет стоимости | Через взвешенную сумму | Через расстояние до идеального решения с минимальной стоимостью | Позволяет выбрать модель, которая находится ближе к оптимальному соотношению качества и стоимости |
| Учет размера модели | Через взвешенную сумму | Через расстояние до идеального и анти-идеального решений | Позволяет учитывать требование к вычислительной эффективности LLM |
| Интерпретация результата | Чем больше сумма, тем лучше модель | Чем ближе коэффициент близости к 1, тем ближе модель к идеальному решению | Коэффициент TOPSIS имеет понятную интерпретацию относительной близости к оптимальной альтернативе |
| Подход к компромиссам между критериями | Компенсационный: высокий результат одного критерия напрямую компенсирует низкий результат другого | Компенсационный, но с учетом геометрического расстояния до идеального и анти-идеального решений | Для выбора LLM важно учитывать сбалансированность характеристик, а не только их сумму |
| Пригодность для выбора LLM | Подходит для простого рейтинга | Подходит для многокритериального выбора наиболее сбалансированной модели | Выбор LLM представляет собой многокритериальную задачу с конфликтующими требованиями |
| Сложность реализации | Низкая | Средняя | Дополнительная сложность TOPSIS оправдана необходимостью учитывать идеальную и анти-идеальную альтернативы |
| Итоговый выбор | Используется как простой альтернативный метод | **Выбран в качестве основного метода** | TOPSIS лучше соответствует задаче поиска LLM, максимально близкой к оптимальному сочетанию качества, стоимости, размера и контекстного окна |
